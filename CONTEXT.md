# Context

## Project Domain

Electric is a hands-on AI + electricity trading learning platform. It is a learning prototype, not production trading software.

Core flow:

```text
public electricity data -> forecasting -> market simulation -> strategy/backtest -> explanatory WebUI
```

The current deployment discussion is scoped to the explanatory WebUI only.

## Glossary

### Showcase WebUI

The public website version of Electric. It is a presentation surface that autoplays precomputed Shandong electricity-market data and explains the project. It is not expected to run heavy algorithms live on the server.

Use this term instead of "production app" or "live trading system" for the current deployment.

### Rolling Demo

The pre-baked dashboard payload that drives the WebUI animation. It contains timestamps, load, price, renewable output, strategy ranking, and report summaries.

In showcase deployment it is served as static JSON, not generated on every page load.

### Showcase Explainer

The DeepSeek-backed Copilot role in the public site. It answers plain-language questions about the dashboard, project concepts, algorithms, datasets, and offline reports.

It may read lightweight report/dataset/capability metadata. It must not run live forecasts, market simulations, backtests, or strategy recommendations in showcase mode.

### Offline Report

Generated evidence already stored under `ellectric/reports/`. Reports are safe for showcase Copilot to reference because they do not require recomputation.

### 30-Day Historical Replay

The fixed Showcase WebUI scenario covering 2025-10-01 00:00 through 2025-10-30 23:45 in Shandong market time (UTC+8), with 2,880 historical 15-minute points. Market and strategy displays in this replay use the same window.

Use this term instead of "monthly return" or "October trading result" because the scenario is a historical explanatory replay, not a real account statement.

### Standardized Backtest Day

The day boundary used by the historical strategy evidence: 00:00 through 23:45 in Shandong market time, containing 96 points. A source value labelled 24:00 is normalized to the next day's 00:00.

This is a backtest grouping convention, not a claim about an official market trading-day definition.

### Simulated Spread Value

The comparison value produced by applying a reconstructed directional position to the difference between the historical real-time settlement price and the Daily Backtest Baseline Price, using the backtest's fixed capacity scale.

It is measured in simulated units. It is not RMB profit, revenue, investment return, or a real transaction amount.

### Daily Backtest Baseline Price

The single reference price shared by all 96 points in one Standardized Backtest Day. During the first seven days it is initialized from that day's complete real-time price mean; afterward it is the mean of the preceding seven days.

Use this term instead of "rolling reference price" because the value is fixed within each day.

### Baseline Initialization Period

The first seven days of a replay, when the Daily Backtest Baseline Price uses the complete current-day real-time price mean. Results from this period remain useful for same-method strategy comparison but do not represent a strictly tradable settlement convention.

### Reconstructed Position

The strategy direction and relative strength recovered algebraically from existing backtest settlement evidence when the original point-level action log is unavailable. It ranges from -100% (full short under the backtest scale) to +100% (full long under the backtest scale).

It is not an original model action, actual holding, order, traded MW, or energy volume.

### Active-Period Positive Contribution Rate

The share of non-flat 15-minute periods whose Simulated Spread Value is positive. Periods with an absolute Reconstructed Position below 1% are treated as approximately flat and excluded from the denominator.

Use this term instead of "win rate" when presenting the 30-Day Historical Replay.

### Profit Factor

The sum of positive Simulated Spread Values divided by the absolute sum of negative Simulated Spread Values within one declared evaluation window.

It is not an investment return and not the ratio of average winning trade to average losing trade.

### 106-Day Out-of-Sample Stability Evaluation

The independent strategy evidence covering 2025-10-01 through 2026-01-14 after a training window ending 2025-09-30. It is used to test whether conclusions from the 30-Day Historical Replay persist over a longer window.

Its metrics must not be mixed into the 30-day replay.

### Historical Published Load Forecast

The forecast values included in the historical Shandong source dataset. They are shown as historical market context and are not live predictions or outputs generated by the Showcase WebUI's XGBoost model.

### Strategy Evidence Snapshot

The versioned, pre-baked strategy evidence consumed by the Showcase WebUI. It binds one replay window to its methodology, summary metrics, point-level series, daily aggregates, theoretical upper bound, long-term evidence reference, and provenance.

If its market window or provenance cannot be validated as a complete unit, the 30-day strategy presentation is unavailable rather than partially reconstructed from a different report.

### Live Algorithm Execution

Any server-side operation that loads models, runs ASSUME, runs RL backtests, computes live recommendations, or performs realtime prediction. This is out of scope for the public showcase deployment.

### Hong Kong Showcase Server

The recommended hosting environment for the public demo: small Hong Kong VPS, Ubuntu LTS, FastAPI/uvicorn, static frontend, pre-baked JSON, and DeepSeek API key. Hong Kong avoids mainland ICP filing while keeping acceptable mainland access latency.

### Integrated Pipeline

The canonical 7-stage pipeline that produces the Showcase WebUI data. Consists of: Data Ingestion (ShandongDataLoader + WeatherFetcher) → Load Forecasting (XGBoost) → Price Forecasting (LEAR) → Renewable Output Forecasting (WindPowerForecaster / SolarPowerForecaster) → RL Trading + Backtest (ElectricityMarketEnv + BacktestRunner, PPO/SAC/TD3) → Explainability (SHAP) → Showcase + Copilot (FastAPI + React + DeepSeek).

Use this term instead of "the whole pipeline" or "the flow" when referring specifically to the stages that feed the showcase data.

### Standalone Learning Experiment

An exploratory script or notebook that is not part of the Integrated Pipeline. ASSUME (`ellectric/assume/`) is the primary example — it was used for learning but never received `import assume` in any integrated pipeline module and is not served by the Showcase WebUI.

Use this term instead of "failed experiment" or "not implemented" — the experiment was real, just not integrated.

## Current Deployment Boundary

The public site should do these things:

- Load the WebUI.
- Autoplay the rolling demo.
- Keep Copilot chat available.
- Let Copilot explain concepts in beginner-friendly Chinese.
- Let Copilot query offline reports, datasets, and capability metadata.

The public site should not do these things:

- Run XGBoost/LEAR prediction live.
- Run ASSUME market simulation.
- Run RL backtesting.
- Run trading recommendations.
- Require model artifacts, GPU, ASSUME, PyTorch-heavy dependencies, or paid realtime data.
